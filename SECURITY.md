# Segurança

Use o botão **Report a vulnerability** na aba Security do GitHub quando
disponível. Se o canal privado não estiver disponível, abra uma issue
pedindo contato privado, sem incluir detalhes exploráveis ou dados sensíveis.

Não publique senhas, tokens, códigos de recuperação, chaves, dumps ou dados
de jogadores. Relatos devem indicar revisão, comportamento esperado,
passos mínimos e impacto observado, usando contas e ambientes sintéticos.

A linha mantida é a revisão atual de main e a última release validada.
Node e bases de contêiner devem acompanhar patches de segurança com CI.
Autenticação, autoridade do servidor, conector privado e persistência
exigem regressões funcionais; não remova controles para acomodar testes.
